# 医院护士排班系统需求基线

## 1. 产品范围

系统用于按护士组生成和维护月度长白班排班。部署后由多人通过浏览器远程访问，共享同一份服务端数据。

第一版每天只有“长白班”和“休息”两种状态，不支持夜班、请假、培训、出差等其他班次；不自动识别法定节假日和调休。

## 2. 部署与数据

- 在 VPS 上部署一个 Node.js 轻量服务，同一服务提供前端页面和服务端接口。
- 使用 SQLite 单文件数据库，不依赖 MySQL 等独立数据库服务，不使用 Spring Boot。
- 系统时区固定为 `Asia/Shanghai`。
- 每 2 天凌晨 02:00 创建一次一致性备份，只保留最近 14 天内的备份。
- 备份放在 VPS 独立目录；超级用户可查看最近备份时间和结果。
- 网页不提供数据恢复按钮，恢复由部署人员在服务器上执行。

## 3. 账户与登录

### 3.1 超级用户

- 系统预置唯一超级用户，登录账号固定为 `admin`。
- 超级用户不可改名、删除、停用，也不属于护士组或参与排班。
- 初始密码由 VPS 环境变量配置；首次登录不强制修改，之后可自行修改。
- 超级用户可管理所有账户、护士组、规则、班表、日志和系统状态。

### 3.2 普通账户

- 不提供注册入口，只能由超级用户创建。
- 字段包括：全局唯一且创建后不可修改的登录账号、可修改且允许重名的护士姓名、所属护士组、排班管理权限、启用状态。
- 创建时初始密码统一为 `123456`，页面明确提示；首次登录不强制修改。
- 普通账户可修改自己的密码。密码长度为 6–64 个字符，不强制字符组合。
- 只有超级用户可以把普通账户密码重置为 `123456`，不提供短信或邮箱找回。
- 密码仅保存安全哈希，密码和哈希均不得出现在页面或操作日志中。
- 登录状态保留 7 天；修改或重置密码、停用账户、权限变化后，受影响的旧会话立即失效。
- 普通账户可以暂时未分组，同一时间最多属于一个护士组。
- 普通护士可只读查看所在组所有已生成的过去、当前和未来月排班；默认打开当前月。
- 同组重名时，排班表显示“姓名（登录账号）”。
- 姓名修改后，过去月份保留原姓名快照，当前和未来月份显示新姓名，班次不变。

### 3.3 停用

- 普通账户不永久删除，只允许停用和重新启用。
- 停用后不能登录或进入后续排班，并自动移出当前护士组。
- 停用不改变已有月度排班和操作日志。
- 当前月是否结束其后续排班，由管理员显式执行“结束本月排班”。

## 4. 权限

### 4.1 排班管理权限

- 该权限是操作权限，不是“能否作为护士被排班”的资格。
- 超级用户可为普通账户开启或关闭。
- 该权限完全由超级用户设置，与账户是否仍使用默认密码无关；重置密码不改变该权限。
- 获权账户可管理自己所在组的成员和规则，生成、修改、删除本组当前或下一月排班，并查看本组操作日志。
- 获权账户不能创建、改名、归档或恢复护士组。
- 获权账户只能把未分组普通护士加入本组，或移出本组普通护士；不能移出自己或其他排班管理员。
- 跨组转移以及涉及排班管理员的成员变更，只能由超级用户执行。
- 护士组不强制配置普通排班管理员；缺少时仅显示“仅超级用户管理”，不影响自动排班。

### 4.2 普通护士

- 只能查看和导出本组排班、修改自己的密码、退出登录。
- 不能修改排班、成员、规则或查看日志。

## 5. 护士组

- 系统首次启动时不自动创建护士组，由超级用户创建。
- 新建组默认规则为：工作日每天休息 1 人、每人每月休息 4 天。
- 组名可由超级用户修改。
- 从未生成排班且没有历史记录的空组可以永久删除。
- 存在排班或操作日志的组只能归档；归档组停止自动排班和成员加入，但历史可查看，并可由超级用户恢复。
- 一个账户同一时间最多属于一个组；月度排班保存生成时的成员快照，之后入组、出组和转组不会自动改写已有班表。

## 6. 排班规则

### 6.1 组级规则

- “每人月休天数”是护士组统一规则，不支持个人单独额度，默认 4 天。
- “每日休息人数”是周一至周五每天期望休息的人数，默认 1 人；必须是 0 到当前组员人数之间的整数。
- 周六和周日默认全员长白班，自动排班不得主动安排周末休息。
- 法定节假日和调休按普通星期处理，特殊情况由管理员手工调整。
- 月休天数优先于每日休息人数。两者总量不一致时，保证每人应休天数，并让每日人数偏差最小。
- 如果个人应休天数超过其排班区间内的工作日数量，则本组不能执行一键排班；不得自动使用周末补足。
- 如果成员变化导致每日休息人数超过组员人数，则组配置无效；该组自动排班被跳过。

### 6.2 折算

- 当前月中途生成时，从执行当天排到月末。
- 完整月、当月中途入组或离组均使用同一折算公式：

  `个人应休天数 = 四舍五入（组级月休天数 × 个人排班区间内工作日数 ÷ 当月全部工作日数）`

- 工作日只指周一至周五。

### 6.3 均匀与确定性

- 一键排班必须稳定可复现，相同成员、规则、月份和上月数据产生相同结果，不使用随机数。
- 同一护士的休息日应尽量均匀分散，尽量避免连续两个工作日休息。
- 如果上月已有排班，生成本月时参考上月最后一个工作日，尽量避免跨月连续休息。
- 均匀与避免连续是优化目标，不是阻断规则；无法满足时仍生成并显示规则提示。

### 6.4 规则变更

- 修改组规则不自动改变已有排班单元格。
- 当前月和未来月立即按新规则重新计算文字提示。
- 过去月份继续使用当时保存的规则快照。
- 新规则用于之后的一键排班。

## 7. 月度排班生命周期

### 7.1 创建

- 每个护士组每月最多存在一份月度排班。
- 管理员手工一键排班只允许当前月和下一个月；过去月份和更远月份不能手工生成。
- 当前月从执行当天开始至月末；下一个月覆盖完整自然月。
- 只要目标月班表存在，一键排班按钮就不可用，不能直接覆盖或重排。
- 只有整月删除并确认后，才能再次一键排班。

### 7.2 自动月排班

- 每月 1 日 00:05 自动为尚无当月排班的有效护士组执行一键排班。
- 如果服务错过执行时间，恢复启动后立即补生成缺少的当月排班。
- 已有当月班表绝不覆盖。
- 空组或无效配置只跳过本组，不影响其他组；操作日志操作者为“系统”。
- 自动排班或备份异常只在超级用户的顶部提醒区和系统状态页显示；本组排班页仍说明未生成原因。

### 7.3 修改和删除

- 过去月份只读，不允许修改或删除。
- 当前月和未来月允许手工修改；当前月和下一个月允许整月删除。
- “删除排班”必须二次确认，确认后才删除并恢复一键排班按钮。
- 删除写入不可篡改操作日志。

### 7.4 中途人员变化

- 组成员变化不自动改变已有月度排班。
- 当前月中途入组者可通过“添加到本月排班”从入组当天加入；初始状态均为长白班，再由管理员手工调整。
- 当前月中途离组者通过“结束本月排班”选择离组日期；离组日前记录保留，离组日起至月末留空。
- 空白表示超出个人排班区间，不是第三种班次状态。
- 上述操作均写入操作日志并重新计算规则提示。

## 8. 手工调整与并发

- 管理员点击单元格，在“长白班”和“休息”之间切换。
- 未保存改动高亮，表格下方实时重算规则提示。
- 点击“保存修改”后批量提交；规则不符合时二次确认，但不阻止保存。
- 一次批量保存记为一条日志，列出全部单元格变更。
- 如果保存时班表已被其他人修改，则拒绝保存并要求刷新后重做；不静默覆盖，也不自动合并。

## 9. 规则提示

排班表下方用中文列出具体日期和护士姓名，检查以下偏差：

- 工作日实际休息人数不等于每日休息人数。
- 护士实际休息天数不等于折算后的个人应休天数。
- 护士在周末被手工设为休息。
- 护士出现连续两个工作日休息，包括跨月连续。

提示永远不阻止手工保存。

## 10. 操作日志

- 所有成功的新增、修改、删除操作必须记录；浏览和导出不记录。
- 日志永久保留，任何人（包括超级用户）都不能修改或删除。
- 字段包括：`Asia/Shanghai` 操作时间、操作者姓名与登录账号、所属护士组、操作类型、操作对象、修改前内容、修改后内容、中文摘要。
- 自动任务的操作者显示为“系统”。
- 超级用户可查看全系统日志；排班管理员只可查看本组日志；普通护士不可查看。
- 日志不记录 IP、明文密码或密码哈希。

## 11. 界面与导出

- 使用指定设计库中的 Airtable Inspired 风格：白色画布、清晰表格线、紧凑数据网格、少量柔和状态色。
- 排班表以护士为行、日期为列；左侧固定护士姓名，顶部显示日期与星期，右侧固定个人实际休息合计。
- 周末列浅灰，休息使用明显色块，当前日期高亮；规则提示位于表格下方。
- 手机端固定姓名列，日期区域横向滚动；不开发独立 App。
- 所有能查看排班的账户都能导出当前所选组和月份的 Excel `.xlsx`。
- Excel 包含护士姓名、每日状态、个人休息合计和规则提示，文件名格式为“护士组名称-YYYY年MM月排班.xlsx”。
- 不提供打印、PDF 导出。

## 12. 角色导航

- 超级用户：概览、月度排班、护士组、账户管理、操作日志、系统状态。
- 排班管理员：本组排班、本组成员与规则、本组操作日志、个人设置。
- 普通护士：本组排班、个人设置。
- 系统状态展示自动排班结果和最近备份状态。

## 13. 明确不做

- 用户注册。
- MySQL 等独立数据库服务或 Spring Boot 后端。
- 浏览器本地数据作为权威存储。
- 夜班及其他班次类型。
- 法定节假日与调休日历。
- 短信、邮件、微信、企业微信通知。
- 打印和 PDF 导出。
- 网页内数据恢复。
- 独立手机 App。
